# 数学排版修复：渲染器与样式版本一致

先记录原因和修复范围，再实施。用户提供的Fe径向函数截图中，上下标与主字符近乎同大，嵌套指标互相挤压。

## 根因

直接依赖KaTeX为0.19.1，`main.tsx`从该版本导入样式与字体；`rehype-katex@7.0.1`实际使用嵌套的KaTeX0.16.47生成HTML。新版CSS采用`.katex-sizing`等类名，而旧渲染器输出`.sizing`，对应的缩放、支柱和对齐规则失效。LaTeX源码的上下标分组正确，主题的外层字号规则不是本次根因。

## 实施

- 将直接依赖精确固定到与rehype-katex兼容的0.16.47，同步锁文件并去重，使渲染、样式、字体来自同一版本。
- 保留KaTeX内部的数学字号比例和定位；不使用覆盖上下标字号的CSS补丁。
- 在数值/内容检查中增加渲染器与样式来源版本一致性检查，防止单独升级直接依赖再次破坏显示。
- 在浏览器中检查实际计算字号：一级上下标约为主体的0.7，嵌套脚标约为0.5；验证基线关系、精确用户公式、中英文、桌面和手机的局部公式滚动，并保存截图目视核对。
- 完成后按既有用户身份提交、显式发布一次，核验线上产物。
